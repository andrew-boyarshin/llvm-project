## 2. Calling conventions (`include/llvm/IR/CallingConv.h`)

Add two target-specific IDs after the last allocated one (`CHERIoT_LibraryCall = 127`
in this tree):

Calls between CBC methods use `CallingConv::C`; only the special conventions need IDs:

```cpp
/// Call to a native (AOT) function: clobbers only IR1/FR0.
CBC_Native = 128,
/// Entry method generated by the linker (no arguments, i64 result).
CBC_Entry = 129,
```

Indirect calls need no ID: every indirect call is `CALL_INDIRECT` (E6) with the ordinary C
convention and the full CBC clobber set (`04-architecture.md` §9.6). An earlier version of
this plan had a third ID for per-signature dispatchers; dispatchers no longer exist.

Update `llvm/lib/AsmParser/LLLexer.cpp`/`LLParser.cpp` (`cbc_nativecc`, `cbc_entrycc`
keywords), `lib/IR/AsmWriter.cpp` (printing), and `docs/LangRef.rst` (calling-convention
list). Precedent: the `RISCV_VLSCall_*` and `CHERIoT_*` additions.

Alternative without core IR changes: string function attributes (`"cbc-native"`,
`"cbc-entry"`) interpreted by `CBCISelLowering`. The enum is preferred because calling
conventions survive inlining/cloning/merging and are checked by the verifier.

## 4. MC layer: the `CBC` object format

Precedents: SPIR-V (`lib/MC/MCSPIRVStreamer.cpp`, `lib/MC/SPIRVObjectWriter.cpp`,
`include/llvm/MC/MCSectionSPIRV.h`) and DXContainer (`MCDXContainerStreamer`,
`MCDXContainerWriter`, `MCSectionDXContainer`). CBC is closer to SPIR-V: a module-level
container whose global tables are built by the AsmPrinter.

### 4.1 New files

| File | Content |
|---|---|
| `include/llvm/MC/MCSectionCBC.h`, `lib/MC/MCSectionCBC.cpp` | `MCSectionCBC : MCSection`. One code section per method (`cbc.code.<method>`), plus one `cbc.meta` section. `printSwitchToSection` prints `.section cbc.code.<name>`. |
| `include/llvm/MC/MCSymbolCBC.h` | Symbols carry a kind (method code start, local label, pool entity) |
| `include/llvm/MC/MCCBCStreamer.h`, `lib/MC/MCCBCStreamer.cpp` | `MCCBCStreamer : MCObjectStreamer`. Delegates instruction encoding to the code emitter; forwards CBC directives to the target streamer; owns no tables. |
| `include/llvm/MC/MCCBCObjectWriter.h`, `lib/MC/CBCObjectWriter.cpp` | `MCCBCObjectTargetWriter` (target hook, mostly empty) and `CBCObjectWriter : MCObjectWriter`, which serializes the module (`03-cbc-file-format.md`) in `writeObject()`. |
| `include/llvm/MC/MCAsmInfoCBC.h`, `lib/MC/MCAsmInfoCBC.cpp` | `MCAsmInfoCBC`: comment string `//`, no `.type`/`.size` directives, private label prefix `.L`, `HasDotTypeDotSizeDirective = false`, `SupportsDebugInformation = false`. |

### 4.2 Where the module tables live

The module-level data (strings, terms, references, AOT entries, types, field definitions,
per-method headers, exception regions, liveness positions) is accumulated in a
`CBCModuleBuilder` object owned by the CBC **target streamer**
(`CBCTargetObjectStreamer`, `06-backend.md` §8.7) and handed to `CBCObjectWriter` at
`finish()`. `CBCObjectWriter` only needs from MC: the finished bytes of each code section
and the section offsets of MC symbols (exception region bounds, state-point labels), which
`MCAssembler` provides after layout.

To keep `lib/MC` free of CBC semantics, `CBCObjectWriter` is generic over an interface:

```cpp
class MCCBCObjectTargetWriter : public MCObjectTargetWriter {
public:
  Triple::ObjectFormatType getFormat() const override { return Triple::CBC; }
  /// Produce the file. Called after layout; sections and symbol values are final.
  virtual void writeModule(raw_pwrite_stream &OS, const MCAssembler &Asm) = 0;
};
```

and the CBC target implements `writeModule` in
`lib/Target/CBC/MCTargetDesc/CBCObjectWriter.cpp` with the `CBCModuleBuilder`. (Same split
as `MCWasmObjectTargetWriter` vs `WasmObjectWriter`, but with the serializer on the target
side because the format is target-specific by nature.)

## 7. `ExpandVariadics` (`lib/Transforms/IPO/ExpandVariadics.cpp`)

Add `struct CBC final : public VariadicABIInfo` and `case Triple::cbc:` in
`VariadicABIInfo::create` (line ~1127):

| Hook | CBC implementation |
|---|---|
| `enableForTarget()` | true |
| `vaListPassedInSSARegister()` | false (the host `va_list` is a struct on x86-64/AArch64 Linux) |
| `vaListType(Ctx)` | the host `va_list` type: x86-64 `[1 x {i32, i32, ptr, ptr}]`; AArch64 Linux `{ptr, ptr, ptr, i32, i32}`; Apple arm64 `ptr` |
| `vaListParameterType(M)` | `ptr` |
| `initializeVaList(M, Ctx, Builder, VaList, Buffer)` | store the exhausted-register-area constants and `Buffer` as overflow area (`04-architecture.md` §10.1) |
| `slotInfo(DL, Ty)` | host stack-slot rules: size rounded to 8, alignment `max(8, ABI align)` capped at 16; aggregates > 16 bytes (AArch64) passed indirectly |
| `ignoreFunction(F)` | true for declarations (native functions keep the native variadic convention); **false for `nullptr`** — `expandCall` passes `CB->getCalledFunction()`, which is null for indirect calls, and those must be expanded |

The pass must also skip call sites whose callee is a declaration (a native variadic call).
If the existing pass rewrites all call sites of variadic function *types*, add a
`VariadicABIInfo::ignoreCallSite(CallBase &)` hook returning true for direct calls to
declarations. The pass runs inside the CBC link-time pipeline (`06-backend.md` §10),
**after** `CBCPrepareFunctionAddresses` (whose native-variadic wrappers must be expanded)
and after `CBCNativeCallLegalizer`. Direct calls to native variadic functions are left
untouched and use the plain host ABI (the engine sets `al`, E7).

Indirect variadic calls are expanded like direct ones by the existing loop over indirect
calls in `ExpandVariadics::runOnModule` (`CB->isIndirectCall() && FTy->isVarArg()`). This
is correct because every function pointer of variadic type that the program can form
points to an *expanded* function: CBC variadic definitions are expanded, and the address of
a native variadic function is replaced by the address of a CBC wrapper
(`07-ir-passes.md` §4 step 1). A variadic native function pointer that native code hands
back to the program (for example a `printf` address returned by a native library) would be
called with the buffer convention and is unsupported, like other native-originated
function pointers to variadic functions.

## 8. Runtime libcalls (`include/llvm/IR/RuntimeLibcalls.td`)

Add a `CBCSystemLibrary` with `IsCBC = LibcallPredicate<[{TT.isCBC()}]>`:

* default C library names for `memcpy`, `memmove`, `memset`, `memcmp` (native libc),
  libm entries (`fmod`, `floor`, `ceil`, `trunc`, `round`, `rint`, `nearbyint`,
  `copysign` (only as fallback), `exp`, `log`, …) — the `LibmLibcallImpls` defaults,
* compiler-rt integer routines for `i128`: `__multi3`, `__divti3`, `__udivti3`,
  `__modti3`, `__umodti3`, `__ashlti3`, `__ashrti3`, `__lshrti3` (CBC-compiled builtins),
* `__extendhfsf2`, `__truncsfhf2`, `__truncdfhf2` for `half`,
* `__atomic_*` sized and generic libcalls for > 8-byte atomics,
* no `__stack_chk_fail` (stack protector off by default), no `_Unwind_Resume` (CBC EH
  lowers `resume` itself; `08-exceptions-and-sjlj.md` §4.4).

Which libcalls are native and which are CBC-compiled does not matter to the backend: the
linker resolves each name and the AsmPrinter emits an `AOT` or a CBC method reference
accordingly (`06-backend.md` §8.3).
