# 11 — Testing Strategy, Milestones, Risks

## 1. Principles

* The engine is the oracle. Its parser (`src/cbc/isa_parser.cpp`), raw disassembler
  (`Cbc::RawDisasm`), loader (`Engine::Loader`), rewriter and interpreter are linked
  **unmodified** into test harnesses that live outside the engine tree.
* Every engine quirk the backend works around (`01-cbc-platform-facts.md` §12) gets a
  regression test that would fail if the workaround were removed.
* The documentation in `cbc-engine-initial-stage/agents/isa_reference.md` is not trusted
  for numbers (`02-isa-encoding.md` §9); tests compare against the code.

## 2. Test layers

### 2.1 Target parser and Clang front end

| Suite | Location | Checks |
|---|---|---|
| Triple | `llvm/unittests/TargetParser/TripleTest.cpp` | parsing, normalization, sub-arch, object format, data layout |
| Preprocessor | `clang/test/Preprocessor/cbc-target.c` | macro set per flavour (`09-clang.md` §1.2) |
| ABI parity | `clang/test/CodeGen/CBC/abi-*.c` + `utils/cbc/abi-parity.py` | IR function signatures equal to the native triple's for a generated corpus of 2 000 prototypes (structs/unions of every scalar mix, sizes 1–64 bytes, alignment 1–16, `__int128`, floats, variadics) |
| Driver | `clang/test/Driver/cbc-*.c` | include order, defaults, linker command |

### 2.2 MC layer

* `llvm/test/MC/CBC/encoding-*.s`: one file per format (`06-backend.md` §13.1), `# CHECK:
  encoding: [...]` lines. Seeded with the byte samples in `02-isa-encoding.md` §10.
* `llvm/test/MC/CBC/relax-*.s`: narrow/wide branch selection at the ±32 KiB boundary,
  generic `Bcc` with the split displacement.
* `llvm/test/MC/Disassembler/CBC/*.txt`: every opcode 0x00–0x93, every selector.
* **Differential encoder test** (`llvm/utils/cbc/isa-diff`): a harness linking the engine's
  `IsaParser` that, for a random stream of instructions generated by `llvm-mc`, decodes the
  bytes and compares operand values field by field with the assembler's view. Runs nightly
  over 10^6 instructions.

### 2.3 Object writer

* `llvm/test/MC/CBC/obj-*.s` + `llvm-readobj --cbc-*`: header, pool ordering, hash tables
  (bucket placement under the 31-hash), index arrays, region trailer.
* **Loader test** (`llvm/utils/cbc/cbc-load-check`): links the engine's `Engine::Loader`,
  `Decode::*` and `Resolution::Resolver`, loads a produced `.cbc`, resolves every method
  reference, field reference and term, finds `main`, and rewrites every method (calling
  `Cbc::Rewrite` directly), which exercises frame layout, liveness joins and
  exception-region mapping without executing anything. Any `FATAL` is a test failure.
* Byte-for-byte comparison of hand-assembled `default.cbc`-like samples is *not* expected
  (pool order differs), but structural equality of decoded tables is.

### 2.5 End-to-end on the engine

A `lit` configuration `cross-project-tests/cbc/` (or `llvm-test-suite` with a `cbc-run`
`TEST_SUITE_RUN_UNDER`) that requires the engine (`REQUIRES: cbc-engine`), compiles with
`clang --target=cbc_<host>`, links with `cbc-ld`, runs with `cbc-run`, compares output.

| Suite | Scope |
|---|---|
| `cbc/basic/` | hand-written C programs, one per feature in `04-architecture.md` §16 |
| `cbc/quirks/` | the engine quirks that remain (not accepted for fixing): negative displacement loads (must not be folded), > 3 500 literals (literal budget). A pointer to a local stored in the heap across deep recursion is ordinary frame memory (`04` §5) and lives in `cbc/basic/` |
| `cbc/engine-ext/` | regression tests of E1–E7 as seen from C: functions with > 512 and ~60 000 untyped slots that spill and reload at high slots, under forced stack growth; 9+ FP arguments under forced stack growth (E2); a generated program with > 70 000 distinct method references and > 70 000 field references in one file (E3); function pointers (a CBC sort routine taking a comparator, tables of handlers, comparison and `uintptr_t` round trips, pointers stored in the image by initializers, vtables); a generated program with 5 000 address-taken functions, all called indirectly (no limit, E5 descriptors); native function pointers (`&puts`, `&strcmp` stored in tables and called indirectly; a pointer from native `dlsym` called through `call.indirect`); a call through a null function pointer (expected: diagnostic and abort, exit status of `abort`); `printf` with 1–8 `double` arguments and with more than 8 (stack-passed) mixed `int`/`double` arguments compared with native output (E7); a static local whose address is stored in the heap and read back after deep recursion; `alloca` larger than one segment, freed on return and on a caught exception (E8) |
| `cbc/engine-probe/` | run a program on an engine **without** E5/E6, and on one without E8: both must stop during the rewrite of the entry method (`ld.fnptr` and `ld.fcb`), before any output of the program |
| `cbc/libc/` | native libc behaviour: `printf`/`fprintf`/`snprintf` with mixed `int`/`double`/`char *` arguments compared with native output; `scanf` of `%d %lf %s`; `sinl`, `strtold`, `frexpl` results equal to the `double` functions; `ldiv`/`lldiv`/`imaxdiv` including negative operands; `atexit` ordering with `__cxa_atexit` (C++ static destructors) and `exit()` from a nested call; `signal(SIGPIPE, SIG_IGN)` then a write to a closed pipe (no termination); `signal(SIGINT, handler)` returns `SIG_ERR` with `EINVAL`; `sigaction` with `SIG_IGN` succeeds; `scandir` with `alphasort`; a `qsort` call → link error "not supported on CBC" (negative test) |
| `cbc/phase2/` (**deferred** with phase 2; not part of the current plan) | the same programs built with separate code generation: COMDAT data shared between objects (an inline function's static local, a template static member, vtables of a class used in several objects) has one address program-wide; `extern` data defined in another object; `extern` native data (`stdout`, `environ`) through `IMAGEOF`; pointers between images in initializers; over-aligned data shared between objects → link error |
| llvm-test-suite `SingleSource/UnitTests`, `SingleSource/Regression/C`, `C++` | correctness; tests that fail to link only with "not supported on CBC" are recorded as **UNSUPPORTED** in a checked-in expectation list (`cbc-unsupported.txt`), and a change in that list fails CI |
| llvm-test-suite `SingleSource/Benchmarks`, `MultiSource/Applications/{sqlite3,lua,minisat}` | correctness + performance tracking (the Lua and SQLite shells' `SIGINT` handlers fail cleanly through the signal guards; the programs run without them) |
| libc++ `test/std` subset (no threads, no locales beyond "C") | C++ library |
| libc++abi `test/` | exceptions, RTTI, guards |
| csmith / YARPGen differential | random C programs: native output vs CBC output |

### 2.6 CI

* Pin the engine revision (commit hash) used by CI — a revision that contains E1–E8
  (`13-engine-changes.md`); the `.cbc` format and opcode numbers have no version
  negotiation (magic only), so an engine update can silently change semantics. Re-run the
  differential encoder test, the loader test and `cbc/engine-ext/` on every engine bump.
* Keep one unpatched engine build in CI only for `cbc/engine-probe/`.
* Host: x86-64 Linux runners only in the current work scope. AArch64 runners are added
  with the follow-up flavour (§3, milestone F1).

## 4. Risk register

| # | Risk | Impact | Mitigation |
|---|---|---|---|
| R1 | Engine behaviour differs from what this design assumes (several reference docs are stale) | wrong code | differential tests against linked engine code (§2.2, §2.3); quirk tests (§2.5); pin engine revision |
| R2 | E8 watermark is wrong: a dynamic `alloca` survives its frame, or a `stackrestore` unmaps a still-live segment | dangling pointers or a crash on the next `alloca`, visible under recursion and `longjmp` | engine unit tests for return, unwind, `setjmp`, and segment growth (`13` §11); a C stress test that stores `&local` in the heap, recurses until the fiber stack grows, and reads it back |
| R3 | Literal table overflow (4 096) in large functions | silent corruption in release engines | `CBCLiteralBudget` with a safety margin; function splitting |
| R4 | Interpretation overhead and expensive calls make C++ code slow | adoption | inlining multiplier, devirtualization, measure early (M2) |
| R5 | Host headers assume x86-64 implies SSE/inline asm | compile failures in third-party code | compat headers, `__CBC__` porting guide, report list |
| R6 | Native callbacks unsupported (out of scope; CBC function pointers are non-executable descriptors, `13` §8), and callback-taking libc functions are unsupported too | some libraries unusable (GUI toolkits, event loops, `pthread_create`); C programs using `qsort`/`bsearch`/`ftw` need porting | link-time error naming the function and the use site (`10` §5.5); error when a CBC function is passed to a native function-pointer parameter (`10` §5.6); UNSUPPORTED expectation list in CI; porting guide (use `std::sort`, or compile a C `qsort` into the program); a separate, verified decision may enable callbacks later |
| R7 | `long double` = `double` | precision loss; native `*l` ABI mismatch | warning; calls renamed to the `double` functions, unknown `long double` natives rejected, `%L` formats rejected by clang (`10` §5.4); `TargetLibraryInfo` gating |
| R8 | `al` undefined on x86-64 native variadic calls | wrong output for FP varargs | **resolved by E7** (the engine sets `al = 8`); regression test in `cbc/engine-ext/` |
| R9 | Engine update renumbers opcodes (happened between `isa_reference.md` and the current source) | every `.cbc` breaks | CI on engine bumps; `cbc-ld` embeds the expected engine revision in the entry type name and the startup check compares it with a native symbol exported by `libcbcengine.so` if available |
| R10 | GC stop-the-world waits for a CBC loop without calls | hangs in multi-threaded Cangjie processes | `CBCInsertSafepoints` on by default |
| R11 | > 65 535 method or field references | silent truncation | **resolved by E3** (32-bit counts); regression test in `cbc/engine-ext/` |
| R12 | First-call rewrite latency of huge functions | start-up stalls | function size heuristics; outlining |
| R13 | Marker exceptions depend on the Cangjie helper library (`throwImplicitException`) | EH unusable if absent | the helper library is required by the engine anyway; check at start-up (`__cbc_check_host` probes for the symbol) |
| R14 | glibc headers with `long double` redirection macros behave unexpectedly (a `*l` name redirected to a symbol missing from the rename table) | link-time "long double in its prototype" errors | validate the compat headers and the rename table against each supported glibc version's symbol list (generated, `10` §5.4) |
| R15 | Native C++ code throwing through CBC frames | crash | document: only `noexcept` C APIs may be called natively |
| R16 | Programs deployed on an engine without E1–E8 | E5/E6 or E8 missing: start-up failure (`ld.fnptr` and `ld.fcb` in the entry); E1–E4 or E7 missing: wrong code (E1, E2, E3, E7) or hangs on corrupt input (E4) | the entry probes make a missing E5 or E8 fail before user code; the others cannot be probed — the minimum engine revision is printed in the linker map and release notes, and E1–E8 ship together as one engine patch |
| R17 | (removed: trampoline exhaustion — E5 descriptors have no fixed limit, `13` §9) | — | — |
| R18 | `call.indirect` to a CBC function costs a direct call plus the descriptor check (range check and load, `13` §9); register allocation around it uses the full CBC clobber set even for native targets | somewhat slower indirect-call-heavy code (C++ virtual calls that are not devirtualized) | WholeProgramDevirt and `CalledValuePropagation` first; measure in M3 |
| R19 | Signal-handler installation fails at run time instead of at link time (guards) | a program that depends on its handler (e.g. for cleanup on `SIGTERM`) silently runs without it | compile-time `-Wcbc-signal-handler`; document; `-Werror=cbc-signal-handler` for strict builds |
| R20 | Struct-borne callbacks (`SIGEV_THREAD` in `timer_create`, `mq_notify`, `aio_*`) are not diagnosed | crash when the notification fires | documented limitation (`10` §5.5) |
| R21 | Every link runs LTO and code generation over the whole program (phase 2 postponed) | long link times for large C++ programs | parallel code generation is not available (one partition); keep LTO pipelines lean at `-O0`/`-O1`; revisit D1 only if link time becomes the bottleneck |
| R22 | The AArch64 flavour is designed but not exercised | latent design errors in AArch64-specific parts (HFAs, `sret` in `IR9`, `va_list`) surface only in F1 | keep AArch64 in `CBCTargetInfo` and the preprocessor/type-model tests from M0 on; ABI-parity corpus run for both flavours at the IR level |
